## 배경

- 홈의 "오늘의 새"는 처음에 하루 단위로 정했다가 매번 랜덤으로 충동 변경했다(`app/page.tsx`의 `getRandom()`). 좋은 결정이 아니었다.
- 트리비아 287개 중 식별형 136·생태형 142·계절형 9. 절반이 "몸길이 45cm, 어깨의 흰 반점"류 도감 문장이라 "새의 생활로 초대"라는 홈의 목적과 맞지 않는다. 문제는 "안 읽느냐"가 아니라 "읽을 게 있느냐".
- 방에서 기각된 것: 홈 개인화(SRS 우선 출제, 마스터 종 제외), 카드 뒤집기·탭(사용자: "귀찮다"), 시각을 지어낸 "새벽 5시" 문장(데이터에 시각 없음, 출처 필수).

## User Story

As a 새에 애정이 있는 사람(이름을 이미 알든 모르든),  
I want 매일 모두에게 같은 한 마리가 오고, 그 새가 지금 이 시간에 뭘 하고 있는지 한 문장으로 만나는 것,  
So that 암기와 상관없이 새의 생활에 초대받는 기분으로 아침·점심·저녁에 앱을 열게 된다.

## 원칙 (방 합의)

1. **홈은 모두의 새.** 진도·티어·마스터 여부를 보지 않는다. 개인화는 세션 엔진의 일.
2. **계절 풀은 정직성.** "지금쯤"이라는 시제를 쓰므로 지금 한국에 없는 새는 오늘의 새가 될 수 없다.
3. **사실과 출처는 그대로, 시제만 현재.** 시각을 지어내지 않는다. 시각이 있는 사실만 시각을 쓴다.
4. **사용자 시계에 맞춘다.** 새벽·한낮·해질녘 중 하나만 보여준다. 놓친 순간은 놓친 것.
5. **한 번에 하나.** 세션 엔진(비율표·이유 태그)은 다음 스토리.

## Technical Notes

- `services/species.service.ts`에 `getBirdOfTheDay(date: Date, deps)` 추가. 순수 함수, `recentIds`와 `now`를 주입받아 결정론 보장. `getRandom`은 유지하되 홈에서는 사용하지 않는다.
- 날짜 시드: `YYYY-MM-DD` 문자열을 정수 해시(예: FNV-1a)로 → `rng` 하나 만들어 풀에서 인덱스. 기존 `shuffle`의 rng 주입 패턴과 동일.
- 계절 상수: `lib/season.ts` — `seasonOf(date)`, `SEASON_STATUS: Record<Season, Status[]>`.
- 순간 상수: 같은 파일 또는 `lib/moment.ts` — `momentOf(date)`, 경계 시각.
- 최근 기록 저장소: `lib/birdOfTheDay.store.ts`, `photoFlags.store.ts` 패턴(손상 시 빈 배열 복구).
- 홈 `app/page.tsx`: `getRandom()` → `getBirdOfTheDay(new Date())`, `pickTrivia` → `pickMomentTrivia(species, momentOf(now), dateSeed)`.
- `TriviaCard`: type 칩 옆에 moment 칩. 식별형 칩은 홈에서 사라지므로 퀴즈 힌트 쪽만 남는다.
- 데이터 한계: 계절은 4칸이지 월별 도래 시기가 아니다. "이번 주에 떠난다"는 못 쓴다. 월별은 NIBR·Birds Korea 체크리스트로 다음 데이터 감사 때.
