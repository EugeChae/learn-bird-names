# 친숙도 티어 · 혼동 상대 · 학습자 레벨 (2026-09-20, 2026-09-25 개정)

## 배경
- 130종 전부 `difficulty_tier`가 있었지만 tier 3이 0종이라 "같은 科 유사종 오답" 규칙이 한 번도 발동하지 않았다.
- 1차 시도(9-20)에서 tier 하나에 두 가지 일(친숙도 + 오답 보기 거리)을 시켰더니 까마귀처럼
  "친숙하지만 구별은 어려운" 종에서 기준이 꼬였다. → 9-25에 두 축을 분리했다.

## 세 가지 축
| 축 | 어디에 | 뜻 |
|---|---|---|
| **친숙도 tier** | `Species.difficulty_tier` (1~3) | 이 새를 얼마나 일찍·쉽게 배우나. 1=일상에서 만나고 이름도 대개 아는 새, 2=탐조를 시작하면 곧 만나는 새, 3=탐조인이 아니면 모르는 새 |
| **혼동 상대** | `Species.confusable_with` (id 배열, 대칭) | 필드에서 실제로 헷갈리는 짝. 오답 보기에 우선 등장 |
| **학습자 레벨** | `progress.service.getLearnerLevel()` | 오답 보기를 얼마나 가까운 종에서 뽑나. 종이 아니라 학습자가 정한다 |

사진별 `SpeciesMedia.difficulty_tier`는 "이 사진의 형태(암컷·유조·겨울깃)가 덜 친숙하다"는 뜻으로 친숙도 축에 속한다.

## 학습자 레벨 (`progress.service.getLearnerLevel`)
- 3단계 **절대평가**, 자동 승급, 수동 고정 없음.
- Lv1 → Lv2: tier 1 새의 70% 이상 마스터(연속 3회 정답). 34종 기준 24종.
- Lv2 → Lv3: tier 2 새의 70% 이상 마스터. 50종 기준 35종.
- 순서대로만 오른다(tier 2를 다 외워도 tier 1 미달이면 Lv1).
- **한 번 오르면 내려가지 않는다.** 마스터 판정이 오답 한 번에 리셋되는 구조라 실시간 계산만 하면 경계선에서 흔들리기 때문. 도달 레벨은 `learn-bird-names:learner-level` 키에 저장하고 진도 초기화 시 함께 지운다.
- 진도 대시보드에 현재 레벨, tier별 마스터 현황, 다음 승급 조건("Lv2까지 1단계 새 N종 더")을 그대로 보여준다.
- 사용자가 확보되면 **상대평가 전환** 검토(사용자 결정, 2026-09-25).

## 사진별 티어 스키마
- `SpeciesMedia.difficulty_tier?: 1 | 2 | 3`. 없으면 종 tier.
- 종 tier = 가장 알아보기 쉬운 형태(대표 사진 `media[0]`)의 친숙도. 덜 친숙한 형태 사진에만 더 높은 값.
- 검증기: 종 tier 필수, 사진 tier ≥ 종 tier, `media[0]`에는 금지.
- 헬퍼: `getEffectiveTier(species, media)`, `getMediaUpToTier(species, maxTier)`.

## 데이터 확인 방법
DB는 `public/data/species.json` 파일 하나다. `npm run data-sheet`를 실행하면 `out/species-sheet.html`이 생성되고 브라우저로 열린다(사진·tier·혼동 상대·서식지 표, tier 필터·검색). 편집은 JSON 직접 수정 후 `npm run validate-data`.
