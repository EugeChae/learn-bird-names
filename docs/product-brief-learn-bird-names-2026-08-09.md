**날짜:** 2026-08-09  
**프로젝트:** learn-bird-names  
**타입:** Web Game (반응형, PC + 모바일)  
**레벨:** 2 (중규모)  
**작성:** BMAD Method v6 — Business Analyst

## Executive Summary

한국 새의 이름과 분류를 사진 퀴즈 방식으로 자연스럽게 외울 수 있는 반응형 웹 게임. 초보 탐조인을 주 대상으로 하며, 보면서 틀리면서 저절로 익히는 학습 경험이 핵심이다. "Flags of the World" 앱처럼 반복 노출과 퀴즈를 통해 수백 종의 새를 부담 없이 체계적으로 익힐 수 있도록 한다. 장기적으로는 소규모 공개를 목표로 하며, 구독 모델을 통한 지속 가능성을 고려한다.

---

## Problem Statement

탐조에 관심이 생겨도 새 이름을 외우는 것이 진입 장벽이 된다. 현재 이용 가능한 방법은:
- 도감(종이책)으로 직접 찾아보기
- 실제로 본 새를 eBird로 확인한 후 검색

이 방법들은 수동적이고 반복 학습이 어려워, 새 이름이 체계적으로 누적되지 않는다. 새를 보고 이름을 모르면 경험이 단절되고, 외우지 못하면 탐조의 즐거움이 반감된다.

**왜 지금인가:** 사용자 본인이 탐조에 관심을 갖게 된 직접적인 필요에서 출발. 여름 철새가 아직 머무는 시기에 맞는 학습 도구가 없다.

---

## Target Audience

### Primary User
한국에서 탐조를 막 시작한 초보자. 도감은 있지만 종 이름을 외우는 것이 어렵고, 게임처럼 즐기면서 배우고 싶은 사람.

### Secondary Users
- 새를 전혀 모르는 사람에게 탐조 취미를 권할 때 소개할 수 있는 입문 도구로서의 사용자
- 한국에서는 중급 탐조인이지만 외국 새(북미, 유럽 등)가 궁금한 사람 *(Phase 2 대상)*

### 사용자의 핵심 니즈
1. 새 이름을 반복적으로 노출받아 자연스럽게 기억할 수 있어야 함
2. 틀려도 답을 알 수 있어, 틀리면서 배우는 구조
3. 퀴즈 외에도 다양한 학습 방식이 있으면 좋겠음 *(아이디어 구체화 필요)*

---

## Proposed Solution

### 핵심 게임 모드 (확정)
- **사진 → 이름 퀴즈:** 새 사진을 보고 한국 공식명을 4지선다로 고르기
- **이름 → 사진 퀴즈:** 이름을 보고 맞는 사진을 고르기
- **Taxonomy 퀴즈:** 새를 보고 목(目)/과(科)를 맞히거나, 같은 과 중 다른 종 찾기

### 학습 설계 (브레인스토밍에서 도출, 사용자 검토 완료)
- **난이도 진행:** 친숙하고 시각적으로 고유한 새부터 → 유사 외형 종으로 점진적 확장
- **오답 보기 설계:** 초급은 다른 목(目)에서, 고급으로 갈수록 같은 속(屬) 유사종으로 좁힘
- **스페이스드 리피티션(SRS):** 틀린 새는 더 자주, 맞힌 새는 점점 드물게
- **Taxonomy 도입 시점:** 개별 종을 어느 정도 익힌 후 자연스럽게 연결

### 첫 화면 (확정)
매일 또는 방문마다 랜덤 새 한 종과 트리비아를 보여주는 "오늘의 새" 피처.  
트리비아 유형: 생태 사실 / 식별 포인트 / 계절·서식 정보 — 세 가지 모두 포함.

### 학습 팩 (아이디어 단계, 미정)
퀴즈 형식 외에 기발한 학습 방식을 추가하고 싶으나 구체적 형태는 아직 미정. *(별도 브레인스토밍 필요)*

### 데이터 구조 (확정)
- **Species 마스터 DB:** 한국 공식명, 학명, 영어명, 목/과, 서식지, 난이도 등급
- **SpeciesMedia 테이블:** 종당 복수 사진 (sex / age / plumage / angle 메타데이터 포함)
- 단일 사진으로는 부족 — 암수/계절깃/어린새/비행 자세별 사진 필요

## Business Objectives

1. 이번 달(2026년 8월) 안에 동작하는 프로토타입 완성 — 여름 철새를 외울 수 있는 수준
2. 소규모 공개 후 탐조에 관심 있는 지인이 쓸 수 있는 수준으로 완성
3. 장기적으로 구독 모델(Subscription) 기반의 지속 가능한 서비스로 성장

### 성공 지표
- 8월 말까지 한국 여름 새 30~50종 퀴즈 가능한 프로토타입 동작
- 사용자 본인이 실제로 새 이름을 외우는 경험
- 지인 1~2명이 실제로 사용할 수 있는 공유 가능한 상태

## Scope

### In Scope — Phase 1 (MVP)
- 사진 → 이름 퀴즈 모드
- 이름 → 사진 퀴즈 모드
- Taxonomy 퀴즈 모드 (기초)
- 오늘의 새 + 트리비아 첫 화면
- 한국 새 100~150종 (데이터 수급 상황에 따라 조정)
- 여름 철새 우선 포함 (8월 프로토타입 목표)
- 종 마스터 DB + 멀티 사진 구조
- 스페이스드 리피티션 기반 진도 관리
- 진도 대시보드 (로컬 저장, 로그인 없음)
- 반응형 웹 (PC + 모바일)

### Out of Scope — Phase 1
- 로그인 / 계정 시스템 (로컬 스토리지로 대체)
- 북미·유럽 등 외국 새
- 울음소리 퀴즈 / 음원
- 커뮤니티·소셜 기능
- 네이티브 앱 (iOS / Android)
- 유료 API 사용

### Future (Phase 2+)
- 외국 새 확장 (북미, 유럽)
- 울음소리 학습·퀴즈
- 계정 + 클라우드 진도 동기화
- 구독 모델 구현
- 창의적 학습 팩 *(아이디어 구체화 후)*

## Constraints & Assumptions

### 제약 조건
- **예산:** Phase 1은 무료 서비스만 사용 (유료 API 없음)
- **타임라인:** 2026년 8월 말까지 프로토타입 (약 3주)
- **인력:** 1인 개발 (사용자 본인)
- **사진:** Phase 1은 iNaturalist / GBIF 등 CC 라이선스 사진만 사용
- **트리비아:** 반드시 검증된 출처 기반 수동 작성. AI 생성 콘텐츠 사용 불가. DB에 `trivia_source` 필드 필수

### 가정 (Assumptions)
- NIBR / iNaturalist API로 충분한 한국 새 데이터를 무료로 수집 가능하다
- Phase 1 범위(30~50종)의 사진 큐레이션은 3주 내 수동으로 가능하다
- 로컬 스토리지 진도 저장으로 Phase 1에서 충분한 사용 경험이 가능하다
- 구독 모델 도입 전 무료 공개로 소규모 사용자 확보가 가능하다

## Risks

| 리스크 | 가능성 | 대응 전략 |
|---|---|---|
| 사진 라이선스 이슈 | 중간 | iNaturalist CC-BY-NC 우선 사용; 개별 허가 필요한 BirdForum은 Phase 2 이후 검토 |
| 데이터 수집 병목 | 높음 | 30~50종으로 범위 제한; NIBR API 먼저 테스트 후 수동 보완 |
| 3주 타임라인 | 높음 | 퀴즈 1개 모드 + 여름 새 30종으로 프로토타입 범위 최소화 |
| 학습 팩 아이디어 미정 | 낮음 | Phase 1에서는 퀴즈 모드만; 학습 팩은 Phase 2 브레인스토밍 과제 |
| **트리비아 오정보** | **높음** | **AI 생성 트리비아 사용 금지. 모든 트리비아는 신뢰할 수 있는 출처(도감, 국립생태원, 학술 자료 등)에서 수동 작성·검수 필수. 출처 명시 필드를 DB에 포함** |
