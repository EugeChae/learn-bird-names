# 브레인스토밍 세션: 한국 새 학습 게임 — 난이도 설계 & 데이터 소스

**날짜:** 2026-08-08  
**목표:** 초보자가 보면서 저절로 외워지는 새 이름 퀴즈 게임의 난이도 진행 구조를 설계하고, 한국 새 데이터를 어디서 가져올지 파악한다  
**맥락:** 웹(PC+모바일), Flags of the World 앱 메카닉에서 착안, 사용자 자신이 초보자  
**사용 기법:** SCAMPER · Reverse Brainstorming · Starbursting

---

## 기법 1: SCAMPER — Flags of the World를 새 게임에 적용

"Flags of the World"의 핵심 루프:  
> 국기 이미지 → 나라 이름 4지선다 / 나라 이름 → 국기 4지선다  
> 틀린 것은 자주, 맞춘 것은 점점 드물게 — 모르는 것에 집중

### Substitute (대체)

| Flags 요소 | 새 게임 대응 요소 |
|---|---|
| 국기 이미지 | 새 사진 (또는 삽화) |
| 나라 이름 | 한국 도감 공식명 (예: 까치, 쇠백로) |
| 대륙/지역 묶음 | 목(Order) / 과(Family) 묶음 |
| 4지선다 | 초급 2지 → 중급 4지 → 고급 6지로 확장 |

### Combine (결합)

- **이름 퀴즈 + 사진 퀴즈**를 한 세션 안에 섞기  
- 정답 공개 시 자동으로 분류 정보 노출 → "까치는 **참새목 까마귀과**입니다" (taxonomy passthrough)  
- **Learn mode**(보여주기) + **Test mode**(맞히기)를 하나의 흐름으로: 새 새를 만나면 3초 이름+과 보여주고 바로 퀴즈

### Adapt (적용)

- **스페이스드 리피티션(SRS)**: 틀리면 다음 5장 안에 다시 등장, 3회 연속 정답이면 "숙지됨" 처리  
- **혼동 종 페어링**: 오리류 구별 전까지는 오리과끼리 묶어서 같이 학습; 헷갈리는 것끼리 같이 틀리게 디자인  
- **힌트 단계 축소 원칙**: 초급은 서식지 이모지(🌊 수변, 🏙 도심) 힌트 제공 → 고급은 힌트 없음

### Modify (변형)

- **선택지 난이도 조정**: 초급 오답은 다른 과(科)에서 뽑기 → 고급은 같은 과 내 유사종  
- **크기 척도 표시**: 처음에는 사진 옆에 손바닥/성인 대비 크기 실루엣 — 나중엔 제거

### Put to other uses (전용)

- **목/과 드릴**: "이 4마리 중 까마귀과가 아닌 것은?" 제거 게임  
- **스트릭 모드**: 일일 10문제 스트릭으로 리텐션 유도  
- **실루엣 모드**: 색 제거 검은 실루엣만 보고 이름 맞히기 (최고 난이도)

### Eliminate (제거)

- 초반에 긴 설명 텍스트 없애기 — 사진이 먼저, 이름이 두번째  
- 완전 초보 단계에서는 아종/계절형 정보 숨기기

### Reverse (역전)

- "**이 설명이 틀린 이유는?**" — 이름은 맞지만 사진이 다른 종인 경우를 보여주고 잡아내기  
- "**이 과(科)가 아닌 새를 고르세요**" — 소거 방식 taxonomy 퀴즈

## 기법 2: Reverse Brainstorming — "이 게임이 실패하려면?"

### 실패 보장 방법 (Anti-solutions)

1. 첫 화면에 솔새류·멧새류처럼 비슷하게 생긴 새부터 출제  
2. 틀렸을 때 "오답입니다"만 표시, 정답 설명 없음  
3. 한국 조류 560종을 분류 없이 한꺼번에 제시  
4. 오답 보기를 무작위로 뽑아서 어떤 문제는 너무 쉽고 어떤 문제는 갑자기 어려워짐  
5. 진도 표시 없음 — 얼마나 외웠는지 모름  
6. 처음부터 taxonomy 외우기 강요  
7. 사진 품질이 들쭉날쭉 (어떤 건 박물관 표본, 어떤 건 역광 필드샷)  
8. 크기·서식지 맥락 전혀 없음 — 물닭과 비둘기 비교  

### 역전된 설계 원칙 ✅

1. **친숙도 우선 배열**: 이미 아는 새부터 → 자신감 구축 후 낯선 새 도입  
2. **오답 공개 시 풍부한 피드백**: 정답 사진 + "이 새와 다른 점: 부리 모양, 눈선"  
3. **그룹 잠금 해제 구조**: 5~10종 묶음으로 분할, 묶음 완료 시 다음 묶음 개방  
4. **스마트 오답 설계**: 난이도=오답 보기의 거리감 (초급: 다른 과 → 고급: 같은 속)  
5. **진도 대시보드**: "숙지 23마리 / 전체 560종 중 현재 구간 50종"  
6. **Taxonomy는 나중에**: 개별 종 30마리 숙지 후 자연스럽게 과(科) 연결 소개  
7. **사진 큐레이션 기준**: 균일한 앵글(측면 or 3/4), 자연광, 충분한 해상도  
8. **크기·서식지 메타데이터**: 초급에는 힌트로, 고급에는 퀴즈 요소로 전환

## 기법 3: Starbursting — 난이도 변수 체계적 탐색

### WHO — 누가 "쉬운 새"인가?

- **이미 아는 새**: 도시 거주자라면 비둘기, 참새, 까치, 까마귀, 제비는 이미 앎
- **쉬운 새의 특성**:
  - 유일한 시각적 정체성 (원앙: 세상에 없는 색깔 조합)
  - 큰 크기 (두루미, 황새 — 못 헷갈림)
  - 문화적 친숙도 (까치 = 설날 상징, 제비 = 흥부전)
  - 한국 서식 과(科) 내 유일종 (황새: 황새과 1종)

### WHAT — 무엇이 난이도를 만드는가?

**5가지 난이도 축:**

| 축 | 쉬움 | 어려움 |
|---|---|---|
| 시각적 고유성 | 원앙, 두루미 (독보적 외형) | 솔새류 (회갈색, 다 비슷) |
| 과 내 종 수 | 황새과 1종 | 오리과 30+종 |
| 계절 변이 | 연중 동일 (까치) | 여름깃/겨울깃 다름 (도요류) |
| 크기 | 대형 (왜가리, 백조) | 소형 (박새류, 솔새류) |
| 도시 접근성 | 도심 상주 (비둘기, 참새) | 심산 희귀종 (솔개) |

### WHERE — 어디서 만나는 새로 그룹 짓기 (학습 흥미 유지)

```
그룹 A — 내 동네 새  비둘기, 참새, 까치, 까마귀, 제비, 박새
그룹 B — 공원·하천 새  청둥오리, 흰뺨검둥오리, 왜가리, 백로류
그룹 C — 바닷가·저수지  갈매기류, 오리류 심화, 물닭
그룹 D — 산·숲 새  딱새, 지빠귀류, 멧새류
그룹 E — 대형 희귀 새  두루미, 황새, 저어새, 노랑부리저어새
그룹 F — 도전 그룹  솔새류, 도요류, 맹금류 구별
```

### WHEN — 언제 다음 난이도로 전진하는가?

- **그룹 내 80% 정확도** → 다음 그룹 잠금 해제  
- **틀린 새**: 해당 그룹 내 더 자주 등장 (SRS)  
- **Taxonomy 퀴즈 도입 시점**: 같은 과 새 5종 이상 숙지 후

### WHY — 왜 taxonomy를 나중에 가르쳐야 하는가?

- 처음부터 "참새목 참새과 참새"를 외우는 것은 개별 새조차 모르는 상태에서 추상 계층을 도입하는 것 → 인지 과부하  
- 개별 종을 먼저 안 후, "야, 얘네 다 까마귀과네" 하는 **발견의 순간**이 taxonomy를 자연스럽게 기억하게 만듦  
- Flags of the World에서도 나라를 먼저, 대륙/지역을 나중에 정리하는 흐름과 동일

### HOW — 어떻게 구현하는가?

**유사종 오답 풀(distractor pool) 설계 규칙:**

```
난이도 1 (입문): 오답 = 다른 목(目)에서 추출
난이도 2 (초급): 오답 = 같은 목, 다른 과(科)
난이도 3 (중급): 오답 = 같은 과, 다른 속(屬)
난이도 4 (고급): 오답 = 같은 속, 유사 외형 (계절형 포함)
난이도 5 (전문): 오답 = 아종(亞種) 또는 암수 차이
```

## 핵심 인사이트 요약

### 인사이트 1: "친숙도 우선, 분류 나중" 원칙
**설명:** 난이도는 분류학적 희귀도가 아닌 시각적 고유성 + 생활권 친숙도로 정의해야 한다  
**근거:** SCAMPER(대체) + Reverse Brainstorming(역전 #1, #6)  
**임팩트:** 높음 / **구현 난이도:** 낮음  
**왜 중요한가:** 이걸 틀리면 첫 경험에서 이탈. 까치부터 시작하면 누구나 "아 이거 알아!" 하고 계속함

### 인사이트 2: 오답 보기의 거리감 = 난이도 레버
**설명:** 난이도 조절의 핵심은 문제 수나 시간이 아니라, 오답 보기를 같은 과에서 얼마나 가깝게 뽑느냐  
**근거:** SCAMPER(변형) + Starbursting(HOW)  
**임팩트:** 높음 / **구현 난이도:** 중간  
**왜 중요한가:** 구현 가능한 단일 파라미터로 무한한 난이도 스펙트럼 생성 가능

### 인사이트 3: Taxonomy는 "발견" 이벤트로 설계
**설명:** 과(科) 정보를 처음부터 외우게 하지 말고, 같은 과 종들을 여럿 알게 됐을 때 "공통점 찾기" 퀴즈로 자연 도입  
**근거:** Reverse Brainstorming(#6) + Starbursting(WHEN, WHY)  
**임팩트:** 높음 / **구현 난이도:** 중간  
**왜 중요한가:** 게임의 핵심 차별점 — taxonomy 앱은 많지만 이 순서로 가르치는 것은 드뭄

### 인사이트 4: 서식지 그룹이 분류학 그룹보다 초보자 동기 유발에 효과적
**설명:** "내 동네 새", "하천 새", "바닷가 새"로 그룹을 짜면 사용자가 일상에서 게임과 연결됨  
**근거:** Starbursting(WHERE)  
**임팩트:** 중간 / **구현 난이도:** 낮음  
**왜 중요한가:** 앱 밖에서 새를 보는 경험이 게임 복귀 동기가 됨

### 인사이트 5: 이미지 품질 기준이 데이터 설계의 병목
**설명:** NIBR + iNaturalist 사진은 품질 편차가 크다. 초기 MVP에서는 종당 1~2장의 큐레이션된 사진을 수동으로 선별해야 할 것  
**근거:** Reverse Brainstorming(#7)  
**임팩트:** 높음 / **구현 난이도:** 높음  
**왜 중요한가:** 사진 품질이 낮으면 게임 자체가 성립 안 됨

## 한국 새 데이터 소스 정리

### 1순위: NIBR 국가생물종지식정보시스템
- **URL**: https://species.nibr.go.kr/
- **포함 데이터**: 한국 도감 공식명, 학명, 목/과/종 분류, 사진
- **API**: 있음 (data.go.kr 공공데이터포털 연계)
- **라이선스**: 공공데이터 공개
- **용도**: 공식 한국명 + 분류 체계의 정본

### 2순위: GBIF API
- **URL**: https://techdocs.gbif.org/en/openapi/v1/occurrence
- **포함 데이터**: 한국 조류 출현 기록 ~590종, 사진 (iNaturalist 연계)
- **API**: REST API 완비
- **라이선스**: CC0 / CC-BY / CC-BY-NC (사진마다 다름)
- **용도**: 사진 소스 + 분포 데이터

### 3순위: Birds Korea 2024 체크리스트
- **URL**: https://www.birdskoreablog.org/
- **포함 데이터**: 617종, IOC 명명 기준, 영문명 포함
- **API**: 없음 (PDF)
- **라이선스**: 오픈 다운로드
- **용도**: 종 목록의 기준점, NIBR 교차 검증

### 4순위: iNaturalist API
- **URL**: https://api.inaturalist.org/v1/
- **포함 데이터**: 한국 조류 관찰 기록 + CC 사진
- **API**: REST API 완비, 무료
- **라이선스**: CC-BY-NC (대부분)
- **용도**: 풍부한 현장 사진 소스

### 참고: Avibase
- **URL**: https://avibase.bsc-eoc.org/checklist.jsp?region=KR
- **포함 데이터**: 한국 593종, 사진·음원 링크
- **API**: 제한적 (주로 웹 브라우징)
- **용도**: 종 목록 검증 및 탐색용

### 한국 새 규모
- 한국 기록 조류: **약 560~617종** (자료마다 편차)
- MVP 추천 범위: **100~150종** (친숙하고 사진 구하기 쉬운 것부터)
- 장기 목표: 전체 종 커버

## 추가 인사이트 (세션 중 도출)

### 인사이트 6: 종당 사진 1장은 학습에 부족 — 멀티 미디어 구조 필수
**설명:** 같은 종이라도 수컷/암컷, 여름깃/겨울깃, 성조/유조, 날 때/앉을 때가 전혀 다르게 보인다. 하나의 사진으로 학습하면 현장에서 다른 자세의 새를 만났을 때 인식 실패.  
**함의:** DB 설계부터 `SpeciesMedia` 테이블을 별도로 두어 sex / age / plumage / angle 메타데이터로 구분 관리. 퀴즈 난이도에 따라 "전형적 자세(쉬움)" vs "비전형 자세/암컷/유조(어려움)" 사진을 선택적으로 사용.  
**사진 소스 후보:** iNaturalist API (CC 라이선스 명확, 다각도 사진 풍부), BirdForum (품질 우수하나 개별 허가 필요), Macaulay Library (고품질, 라이선스 확인 필요)

### 인사이트 7: 자체 종 마스터 DB가 모든 것의 기반
**설명:** 사진·음원은 외부 소스에서 가져오더라도, 종 정보(공식 한국명, 학명, 분류, 특징, 서식지 등)는 직접 관리해야 콘텐츠 확장이 자유로워진다.  
**제안 스키마:**

```
Species (종 마스터)
├── korean_name          # 도감 공식명
├── scientific_name      # 학명
├── english_name         # 대중 영어명
├── order_ko / order_la  # 목
├── family_ko / family_la # 과
├── genus
├── description_ko       # 식별 포인트
├── habitat[]            # [도심, 산림, 수변, 해안]
├── size_cm
├── residency            # 텃새 | 여름철새 | 겨울철새 | 나그네새
└── difficulty_tier      # 1~5

SpeciesMedia (사진/음원)
├── species_id
├── type                 # photo | audio
├── sex                  # male | female | unknown
├── age                  # adult | juvenile
├── plumage              # breeding | non_breeding
├── angle                # side | front | flight | back
├── source               # inaturalist | gbif | manual
├── license
└── quality_score        # 큐레이션 점수
```
